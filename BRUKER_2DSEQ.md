# Загрузка реконструированных изображений Bruker

В **Open file** выберите файл `2dseq`. Размеры из полей X/Y/Z для этого
формата не используются: загрузчик ищет `visu_pars` и `reco` в той же папке.
Существующие ветки `.64`, `.ser` и обычного бинарного float32 не изменены.

## Архитектура

`openFileCallback` → `loadVolumeForApp` → `readBruker2dseq`.
Небольшой `readBrukerParameterFile` разбирает записи JCAMP-DX без `eval`.
Он сохраняет значения параметров текстом, включая объявления массивов,
геометрию и группы кадров. Числовой разбор выполняется для необходимых полей;
поддерживаются многострочные массивы, комментарии `$$`, экспоненты D/E,
повторы `@N*(value)`. Регистр и подчёркивания в именах параметров игнорируются,
в частности `RECO_word_type` и `RECO_wordtype` эквивалентны.

Модель данных приложения сохранена. В базовом workspace появляются:

- `x2dseq` — масштабированное изображение типа `double`, используемое всеми
  существующими функциями визуализации, масок и расчётов;
- `x2dseq__raw` — немасштабированные значения исходного типа в той же ориентации;
- `x2dseq__meta` — исходные параметры `visuPars`/`reco`, пути, размеры,
  тип, endian, источники параметров и применённое преобразование `scaling`.

При совпадении имён добавляется суффикс `_1`, `_2` и т. д. Отдельная структура
`image` не вводится. Функция чтения возвращает `[data, metadata, rawData]`;
диспетчер передаёт исходные значения через `extras.rawData`.

## Определение параметров

| Параметр | Основной источник | Резервный источник |
|---|---|---|
| Размеры | `VisuCoreSize` | `RECO_size` |
| Число кадров | `VisuCoreFrameCount` | Размер файла / размер одного полного core-кадра |
| Тип и знак | `VisuCoreWordType` | `RECO_wordtype` / `RECO_word_type` |
| Порядок байтов | `VisuCoreByteOrder` | `RECO_byte_order` |
| Множитель декодирования | `VisuCoreDataSlope` | `1 ./ RECO_map_slope` |
| Смещение | `VisuCoreDataOffs` / `VisuCoreDataOffset` | `RECO_map_offset` |

Тип определяется по имени enum, а не размеру файла. Поддерживаются signed
и unsigned integer 8/16/32 бит, float32 и float64; также их MATLAB-имена.
`littleEndian` преобразуется в `ieee-le`, `bigEndian` — в `ieee-be`.
Неизвестные размеры, тип или endian вызывают ошибку. Существующий, но
некорректный приоритетный параметр не маскируется резервным значением.

Одного из двух файлов метаданных достаточно. Если отсутствуют оба, чтение
невозможно. Отсутствие slope для integer вызывает ошибку; для float при
отсутствии коэффициента используется 1. Отсутствующий offset считается 0.
Эти допущения и отсутствие файлов записываются в `metadata.notes` и выводятся
предупреждением при загрузке через интерфейс.

## Оси и кадры

Bruker хранит пиксели построчно, начиная с верхнего левого угла. Первый размер
`VisuCoreSize` — число столбцов, второй — число строк. MATLAB `imagesc(A)`
показывает первую ось массива как строки, вторую как столбцы; именно так
работают `displaySelectedCallback` и `CompDisplay`.

Поэтому `[Nx, Ny]` Bruker преобразуется в `[Ny, Nx]` MATLAB:

```matlab
rawData = permute(reshape(stored, [Nx, Ny, Nframes]), [2 1 3]);
```

Для одного кадра это `reshape(stored, [Nx Ny]).'`. Никаких `flip`, `rot90`
или подбора ориентации по изображению нет. При `[Nx, Ny, Nz]` и нескольких
core-кадрах результат имеет форму `[Ny, Nx, Nz*Nframes]`, где сначала меняется
z, затем номер кадра. Коэффициент каждого core-кадра применяется ко всему его
объёму. `squeeze` не используется, поэтому единичные строки/столбцы сохраняются.

Порядок кадров остаётся дисковым. В приложении третья ось — список плоскостей:
это могут быть срезы, эхо или временные кадры. Их исходная семантика остаётся в
параметрах frame groups. Анатомическое переориентирование по
`VisuCoreOrientation`/`VisuCorePosition` и сборка комплексных каналов в этом
загрузчике не выполняются. `RECO_transposition` не применяется повторно к
готовым пикселям. Ненулевой дополнительный `VisuCoreTransposition` отклоняется
с понятной ошибкой, поскольку требует отдельной обработки геометрии.
Если доступны только `RECO_size` и ненулевой `RECO_transposition` для
неравных осей, также требуется `VisuCoreSize`: загрузчик не угадывает
окончательные размеры транспонированной реконструкции.

## Масштабирование

При наличии Visu:

```matlab
data = double(rawData) .* VisuCoreDataSlope + VisuCoreDataOffs;
```

При резервном чтении коэффициентов RECO:

```matlab
data = double(rawData) ./ RECO_map_slope + RECO_map_offset;
```

Каждое поле сначала ищется в Visu, затем в RECO; оба slope одновременно
не применяются. Коэффициенты могут быть скалярами или массивами по одному
значению на core-кадр. Неверная длина, NaN/Inf и нулевой slope отклоняются.
Ненулевые коэффициенты применяются и к float, если указаны в метаданных.
`metadata.scaling.applied = true` фиксирует выполненное преобразование.
Визуализация регулирует только цветовой диапазон, повторного rescale в ней нет.

Семантика Visu сверена с опубликованной реализацией
[Bruker readBruker2dseq](https://raw.githubusercontent.com/philippboehmsturm/antx/master/mritools/pvtools_bruker/pvtools_bruker/functions/readBruker2dseq.m).
Обратный RECO slope и аддитивный offset также используются в
[Aedes readbruker](https://github.com/mjnissi/aedes/blob/master/aedes_readbruker.m).

## Проверки

До чтения проверяется точный размер в байтах:
`prod(coreSize) * frameCount * bytesPerElement`. После `fread` проверяются
число элементов, позиция файла и ошибка чтения. Неполный или лишний элемент
не игнорируется. Если число кадров выводится только из размера файла,
отличить лишний целый кадр от намеренно записанного без метаданных невозможно.

Запуск из корня проекта:

```matlab
validate_bruker_loader
validate_bruker_loader('D:/Current projects/Immobilized cat/raw data/99/pdata/1/2dseq')
```

Проверки включают асимметричные неквадратные кадры, порядок осей, разные
коэффициенты и ненулевые offsets, оба endian, signed/unsigned/float, неполные
метаданные, ошибочные параметры и длины файлов, трёхмерные core-кадры и
регрессию обычного float32/CSI-чтения. Исходный тестовый набор не изменяется.
Также проверяется реальный callback загрузки (с заменой только диалога выбора
файла), сохранение в workspace, уникальность имён и передача обоих кадров
в существующую функцию отображения срезов.

Существующие `.exe` и `.mlappinstall` — ранее собранные версии. Для получения
этой поддержки в установленном приложении потребуется пересборка; запуск
исходного `test.mlapp` использует обновлённые функции `private`.
